# AIOPS 智能运维平台 — 生产环境部署文档

本文档描述 AIOPS 平台（Go 后端 + Python 算法服务 + Vue 前端 + Qdrant + MySQL）在生产环境（以 Linux 为例）的完整部署步骤。当前仓库没有 Dockerfile 与 CI/CD，部署为手动/脚本化流程。

## 1. 架构与组件清单

| 组件 | 技术 | 默认端口 | 生产暴露方式 |
|------|------|----------|--------------|
| 前端 | Vue 3 + Vite 静态资源（hash 路由，base `./`） | 80/443 | Nginx 对外提供 |
| Go 后端 | Gin（`cmd/center` 编译产物 `center`） | :8080 | 仅 Nginx 内部反代，不对公网开放 |
| Python 算法服务 | FastAPI + uvicorn（知识库解析/向量化/检索） | :9000 | 仅 Go 后端访问，**必须绑定 127.0.0.1**，无鉴权 |
| Qdrant 向量库 | Docker 容器 v1.11.x | 6333/6334 | 仅本机访问（Python 服务使用） |
| MySQL | 8.x，库名 `aiops`，utf8mb4 | 3306 | 仅 Go 后端访问 |

数据流：浏览器 → Nginx（静态资源 + `/api` 反代）→ Go 后端（:8080）→ MySQL；Go 后端 → Python 服务（:9000）→ Qdrant（:6333）。

## 2. 环境准备

| 依赖 | 版本要求 | 用途 |
|------|----------|------|
| MySQL | 8.x | 平台元数据库 |
| Docker + docker compose | 任意近期版本 | 运行 Qdrant |
| Nginx | 1.20+ | 前端托管与反向代理 |
| Node.js | 18+ | 构建前端（可在构建机执行） |
| Go | 与 go.mod 一致（当前 1.26.x） | 编译后端（可在构建机执行） |
| Python | 3.12 | 运行算法服务 |

> 前端和后端只需要其构建产物，生产服务器可不装 Node.js / Go（推荐在构建机或 CI 上构建，再把制品传到生产机）。

## 3. 生产目录结构（推荐）

```text
/opt/aiops/
├── backend/
│   ├── center                 # Go 后端二进制
│   └── configs/config.yaml    # 后端配置（数据库等敏感项用环境变量覆盖）
├── uploads/knowledge/         # 知识库上传文件存储（需持久化、纳入备份）
├── algorithm/
│   ├── .venv/                 # Python 虚拟环境
│   └── app/                   # FastAPI 代码（app.main:app）
├── web/                       # 前端构建产物（frontend/dist 内容）
├── qdrant/
│   ├── docker-compose.yml
│   ├── config/config.yaml     # Qdrant 生产配置（见 5.2 说明）
│   └── data/                  # Qdrant 向量数据（需持久化、纳入备份）
└── logs/                      # 各服务日志（systemd journal 或文件）
```

## 4. 制品构建

### 4.1 前端

```bash
cd frontend
npm install
npm run build        # 产物在 frontend/dist，base 为相对路径 './'
```

将 `frontend/dist/` 内容上传到生产机 `/opt/aiops/web/`。

### 4.2 Go 后端

```bash
cd backend
go mod tidy
# 交叉编译到 Linux（在 Windows/Mac 构建机上执行）：
GOOS=linux GOARCH=amd64 go build -o center ./cmd/center
```

> **重要（配置路径陷阱）**：后端通过编译期的源码路径定位 `configs/config.yaml`（`cmd/center/main.go` 的 `getConfigPath`，向上两级 + `configs/config.yaml`），而不是按可执行文件位置定位。因此：
> - 在生产机上应保持 `backend/center` 与 `backend/configs/config.yaml` 同在 `/opt/aiops/backend/` 下，且该目录的**相对层级与编译时一致**；
> - 最稳妥的做法是在生产机上（或与生产品录同路径的机器上）执行编译；
> - 配置缺失时进程启动即 panic（报错「加载配置文件失败」），属于快速失败，不会带错配置运行。

### 4.3 Python 算法服务

纯源码运行，无需构建。生产机执行：

```bash
cd /opt/aiops/algorithm
python3.12 -m venv .venv
./.venv/bin/pip install -r requirements.txt
```

> 不要部署开发用的 `algorithm/.env`（可能含本机密钥）；生产配置用 `KB_` 前缀环境变量（见 6.2）。

## 5. 中间件部署

### 5.1 MySQL

```sql
CREATE DATABASE aiops DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'aiops'@'%' IDENTIFIED BY '强密码';
GRANT ALL PRIVILEGES ON aiops.* TO 'aiops'@'%';
```

- 建表由后端启动时 GORM AutoMigrate 自动完成（含后续版本加列），无需手工导表结构。
- **初始化管理员**：AutoMigrate 只建表和权限/角色/默认模板，**不会创建用户**。首次启动后端（或先建好表）后执行：

```sql
-- 1. 创建管理员用户（注意：当前实现密码为明文存储，见 9.2）
INSERT INTO sys_user (id, username, name, password, created_at, update_at)
VALUES (UUID(), 'admin', '管理员', '初始密码', NOW(3), NOW(3));

-- 2. 创建 admin 角色（后端不会自动创建角色，SeedAdminRoleAuth 只给名为
--    「管理员」或「admin」的角色自动补全全部权限）
INSERT INTO sys_role (id, name, created_at, updated) VALUES (UUID(), 'admin', NOW(3), NOW(3));

-- 3. 绑定用户与角色
INSERT INTO sys_user_role_relation (id, user_id, role_id, created_at, updated_at)
SELECT UUID(), u.id, r.id, NOW(3), NOW(3)
FROM sys_user u, sys_role r
WHERE u.username = 'admin' AND r.name = 'admin' AND u.deleted_at IS NULL;
```

> 执行顺序：先启动一次后端完成建表（AutoMigrate），再执行上述 SQL；之后**再重启一次后端**，`SeedAdminRoleAuth` 才会为 admin 角色补齐全部权限（之后新增权限点也会随启动自动补齐）。

### 5.2 Qdrant（Docker Compose）

仓库根 `docker-compose.yml` 仅编排 Qdrant，内容如下要点：

```yaml
services:
  qdrant:
    image: qdrant/qdrant:v1.11.4
    restart: always
    container_name: qdrant
    ports:
      - "6333:6333"
      - "6334:6334"
    volumes:
      - /opt/aiops/qdrant/data:/qdrant/storage   # 生产建议显式绑定数据目录
    configs:
      - source: qdrant_config
        target: /qdrant/config/production.yaml
configs:
  qdrant_config:
    file: ./config/config.yaml
```

注意事项：

1. compose 文件引用了 `./config/config.yaml`（Qdrant 的 production.yaml），该文件**不在仓库中**，需从 [Qdrant 官方配置模板](https://github.com/qdrant/qdrant/blob/master/config/production.yaml) 获取并按需调整；如果不需要自定义，可删除 `configs` 两段使用镜像默认配置。
2. 仓库中 volume 写的是 `/data/qdrant`，生产上建议改为显式数据目录（如上）。
3. `ports` 只对本机开放即可（Python 服务同机部署时甚至可以不映射端口、走容器网络）。6333 控制台**不要对公网开放**。
4. 启动：`docker compose up -d qdrant`，验证：`curl http://localhost:6333/healthz` 返回 `{"title":"healthz","status":"ok"}`。

## 6. 应用服务部署

### 6.1 Go 后端（center）

**配置文件** `/opt/aiops/backend/configs/config.yaml`：

```yaml
database:
  dsn: ""                      # 生产用环境变量 AIOPS_DATABASE_DSN 注入，勿写明文
server:
  port: ":8080"
app:
  frontend_base_url: "https://aiops.example.com"   # 前端公网地址，用于巡检报告通知里的「完整报告」链接
knowledge:
  python_base_url: "http://127.0.0.1:9000"
  upload_dir: "./uploads/knowledge"                # 相对后端工作目录，注意 systemd WorkingDirectory
```

**环境变量**（优先级高于配置文件，`backend/configs/config.go`）：

| 环境变量 | 说明 |
|----------|------|
| `AIOPS_DATABASE_DSN`（兼容 `DATABASE_DSN`） | MySQL DSN，如 `aiops:强密码@tcp(127.0.0.1:3306)/aiops?charset=utf8mb4&parseTime=True&loc=Local` |
| `AIOPS_SERVER_PORT`（兼容 `SERVER_PORT`） | 监听端口，如 `:8080` |
| `AIOPS_APP_FRONTEND_BASE_URL`（兼容 `FRONTEND_BASE_URL`） | 前端公网地址 |

**systemd 单元** `/etc/systemd/system/aiops-center.service`：

```ini
[Unit]
Description=AIOPS Go Backend
After=network.target mysql.service docker.service

[Service]
WorkingDirectory=/opt/aiops/backend
ExecStart=/opt/aiops/backend/center
Restart=always
RestartSec=5
Environment="AIOPS_DATABASE_DSN=aiops:强密码@tcp(127.0.0.1:3306)/aiops?charset=utf8mb4&parseTime=True&loc=Local"
Environment="AIOPS_APP_FRONTEND_BASE_URL=https://aiops.example.com"
# 更安全的做法：使用 EnvironmentFile=/etc/aiops/center.env（chmod 600）

[Install]
WantedBy=multi-user.target
```

启动：`systemctl daemon-reload && systemctl enable --now aiops-center`。启动日志确认「数据库自动迁移」「告警引擎」「巡检调度器」初始化成功；端口不通时检查 DSN 与配置路径（见 4.2 陷阱）。

### 6.2 Python 算法服务（知识库，可选）

**环境变量**（`KB_` 前缀，`algorithm/app/config.py`）：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `KB_QDRANT_URL` | `http://localhost:6333` | Qdrant 地址 |
| `KB_COLLECTION` | `kb_chunks` | 向量 collection 名 |
| `KB_CHUNK_SIZE` | `500` | 切块目标字符数 |
| `KB_CHUNK_OVERLAP` | `50` | 块间重叠字符数 |

**systemd 单元** `/etc/systemd/system/aiops-analyzer.service`：

```ini
[Unit]
Description=AIOPS Python Analyzer (Knowledge Base)
After=network.target docker.service

[Service]
WorkingDirectory=/opt/aiops/algorithm
ExecStart=/opt/aiops/algorithm/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 9000 --workers 2
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

启动：`systemctl enable --now aiops-analyzer`，验证：`curl http://127.0.0.1:9000/health` 返回 `{"status":"ok"}`。

> `--host 127.0.0.1` 是刻意的：该服务无鉴权，只允许本机 Go 后端访问。

## 7. Nginx 配置（前端 + API 反代）

前端为 **hash 路由**（`createWebHashHistory`）且 base 为相对路径 `./`，Nginx **无需** `try_files` 重写规则；可将 `web/` 挂到任意子路径。

```nginx

user  nginx;
worker_processes  auto;

error_log  /var/log/nginx/error.log notice;
pid        /var/run/nginx.pid;


events {
    worker_connections  1024;
}


http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    sendfile        on;
    #tcp_nopush     on;

    keepalive_timeout  65;

    gzip  on;


    server {
        listen 80;

        root /opt/aiops/web;
        index index.html;

        location / {
            try_files $uri $uri/ /index.html;   # hash 路由下其实不会命中回退，写上无害
        }

        # 后端 API，含 SSE（对话流式 /api/chat/sessions/:id/stream）
        location /api/ {
            proxy_pass http://127.0.0.1:8080;
            proxy_http_version 1.1;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;

            # SSE 必需：关闭缓冲与缓存，否则对话流式输出会被截断/延迟
            proxy_buffering off;
            proxy_cache off;
            proxy_set_header Connection '';
            proxy_read_timeout 600s;            # 大模型响应慢，读超时放宽
            proxy_send_timeout 600s;
            add_header X-Accel-Buffering no;    # 兼容部分网关
        }
    }
}

```

`nginx -t && systemctl reload nginx`。


| 项目      | 路径                      |
| ------- | ----------------------- |
| 配置文件    | `/etc/nginx/nginx.conf` |
| 站点配置目录  | `/etc/nginx/conf.d/`    |
| 默认网站根目录 | `/usr/share/nginx/html` |
| 日志      | `/var/log/nginx/`       |

启动顺序：**MySQL → Qdrant → Go 后端 → Python 服务 → Nginx**。

| # | 验证项 | 方法 | 预期 |
|---|--------|------|------|
| 1 | Qdrant | `curl localhost:6333/healthz` | `status: ok` |
| 2 | Python 服务 | `curl 127.0.0.1:9000/health` | `{"status":"ok"}` |
| 3 | 后端存活 | `curl -i localhost:8080/api/auth/info` | 401（未带 token，路由存在） |
| 4 | 前端 | 浏览器打开 `https://aiops.example.com` | 登录页正常 |
| 5 | 登录 | admin + 初始密码 | 返回 token，进入对话页 |
| 6 | LLM 配置 | 页面配置对话模型与向量化模型并设默认 | 保存成功（向量化模型参见 README「运维知识库」推荐表，DeepSeek 无 Embeddings 接口） |
| 7 | 数据源 | 接入 Prometheus/ES/Pyroscope 并测试连通 | 连通成功 |
| 8 | 对话 | 对话页提问「查询 xxx 指标」 | SSE 流式输出，无截断（验证 Nginx SSE 配置） |
| 9 | 告警 | 建一条必触发规则（持续 0s） | 告警事件页出现 firing 事件 |
| 10 | 知识库 | 上传小文档 → 索引 → 检索 | 状态「已索引」，检索命中；失败时看 `kb_document.error_msg` |

## 9. 安全与运维注意事项

### 9.1 网络暴露面

- 只对外暴露 80/443；8080/9000/6333/3306 一律绑定内网或 127.0.0.1。
- Qdrant 6333 控制台、Python 9000 均无鉴权，泄露即数据失守。

### 9.2 已知安全债（上线前评估）

1. **密码明文存储**：`sys_user.password` 为明文直接比对（`controllers/auth.go:136`），且列宽 varchar(30) 无法存 bcrypt 哈希。建议后续改为 bcrypt/hashing 并加宽列。
2. **登录令牌内存存储**：token 为内存 UUID map（`controllers.GlobalTokenStore`），意味着：
   - 后端**重启即全员掉线**，需重新登录；
   - **不能多副本水平扩展**（副本间会话不共享），生产按单实例部署。
3. `configs/config.yaml` 历史上有明文数据库密码的写法，生产一律用 `AIOPS_DATABASE_DSN` 环境变量注入。
4. LLM API Key 存于 `llm_config.api_key`（数据库），接口已做脱敏，但数据库本身要纳入访问控制与备份加密范围。

### 9.3 数据备份

| 数据 | 位置 | 备份方式 |
|------|------|----------|
| 平台元数据（用户/配置/告警/巡检/知识库元数据） | MySQL `aiops` 库 | mysqldump 定时任务 |
| 知识库上传文件 | `/opt/aiops/uploads/knowledge/` | 文件级 rsync/快照 |
| 向量数据 | `/opt/aiops/qdrant/data/`（容器内 `/qdrant/storage`） | 停机快照，或 Qdrant [快照 API](https://qdrant.tech/documentation/snapshots/) |

恢复顺序：MySQL → Qdrant 数据 → 上传文件目录 → 启动服务。

### 9.4 升级流程

1. 备份（9.3）。
2. 前端：重新 `npm run build`，替换 `web/`。
3. 后端：重新编译 `center`，`systemctl restart aiops-center`；**AutoMigrate 会自动加列**（注意个别版本可能需要先手动 ALTER，如历史上 `llm_config` 列宽调整）。重启会中断会话与告警引擎计时，选择低峰期。
4. Python：替换 `algorithm/` 源码，`systemctl restart aiops-analyzer`（若 embedding 模型维度变更，需重建 Qdrant collection，见 README 知识库章节）。
5. 回归验证清单第 4–11 项。

## 10. 故障排查速查

| 现象 | 排查方向 |
|------|----------|
| 后端启动 panic「加载配置文件失败」 | 配置路径陷阱（4.2）：`configs/config.yaml` 不在编译期路径相对位置 |
| 后端 panic「连接数据库失败」 | DSN、`AIOPS_DATABASE_DSN` 是否生效、MySQL 监听地址与账号授权 |
| 对话流式输出卡住/一次性吐出 | Nginx 未关 `proxy_buffering`（第 7 节 SSE 配置） |
| 知识库索引失败 502 | `kb_document.error_msg`；向量化模型是否支持 Embeddings（DeepSeek 不支持）；API Key 有效性 |
| 巡检报告通知链接打不开 | `AIOPS_APP_FRONTEND_BASE_URL` 未配置为公网地址 |
| 登录后频繁掉线 | 后端被重启（令牌内存存储）或跑了多个后端实例 |
| 告警规则不触发 | 规则是否启用、评估频率、PromQL 在数据源是否可查、持续时间设置 |
